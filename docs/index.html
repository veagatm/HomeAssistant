LAYER 7 OSI analogue — Application

Dashboards & notifications

Where a person actually touches the system — three purpose-built dashboards over the same entities, plus push notifications and voice/display output.

DASH-01Mobile dashboard8 views — home, rooms, presence, laundry, automations, energy, cameras, garden
DASH-02Kitchen kiosk panelWall-mounted display, always-on view
DASH-03Desktop command center3-panel layout — overview, cameras, garden
NOTIFY-01notify.all_phonesPushes to both residents' phones at once
A/V-OUTNest Hub · Google Home · ChromecastVoice and ambient display output
// why

Same underlying entities, three different dashboards — a phone in a pocket, a screen bolted to a kitchen wall, and a monitor on a desk are three different jobs, not one responsive layout stretched three ways.

LAYER 6 OSI analogue — Presentation

Automation logic

Native Home Assistant YAML — the decision-making layer that turns raw events into light changes, alerts, and routines.

LOGIC-01automations.yaml83 automations — presence, lighting, cameras, irrigation, laundry, code enforcement
LOGIC-02helpers.yaml48 input_boolean / input_datetime / input_number / counter helpers
LOGIC-03scripts.yaml14 scripts — snooze system, find-phone, good-night routine
LOGIC-04packages/2 MQTT sensor-bridge packages (bird tracker, code enforcement)
// why

Every automation gets two off-switches: a room-level toggle that silences everything in that room at once, and a per-automation toggle for surgical control — plus a snooze helper that's just a timestamp in the future, checked against now().

None of it needs a YAML edit or a restart to use.

LAYER 5 OSI analogue — Session

Vision & intelligence

Docker services on the Mac Mini that turn raw camera frames into structured events — object detection, face recognition, OCR, and species/vehicle classification.

VIS-01Frigate NVRObject detection + built-in face recognition, CPU-only detector
VIS-02code-enforcementEasyOCR + perceptual-hash vehicle fingerprinting, 2 camera sources
VIS-03bird-trackerSpecies classification on the backyard feeder zone
VIS-04vehicle-dashboardStreamlit review UI for correcting detections, port 8501
VIS-05reid-serviceInsightFace/FAISS re-ID — built, currently stopped
// why

The original design here was CompreFace + Double Take + that InsightFace/FAISS re-ID service. It worked — then started OOM-killing itself under Colima.

Replaced with Frigate's own built-in face recognition: simpler, cheaper to run, does the same job. The re-ID service stays on disk, stopped, in case a street-facing camera ever gets added.

LAYER 4 OSI analogue — Transport

Protocol bridges

The translation layer — every device protocol and cloud API gets normalized into HA entities or MQTT topics here.

BUS-01Zigbee2MQTTVia the ZBT-2 — coordinates every Zigbee sensor
BUS-02Mosquitto MQTT brokerCentral event bus — frigate/events, code_enforcement/*, birds/*
API-01Kasa · LocalTuya · Govee LocalLocal-LAN device integrations (HACS)
API-02Native Reolink integrationLocal — floodlight camera + light entities
API-03August · Leviton ldata-ha · ecobeeCloud integrations — no local API exists
// why

Local-first is the default, not a slogan: every device gets its local-API integration if one exists. Cloud only shows up where no local alternative exists at all — the lock and the energy monitor.

LAYER 3 OSI analogue — Network

Compute hosts

The two machines doing the actual work — one dedicated appliance, one repurposed general-purpose box.

HOST-01HA Green (HAOS)The automation brain — runs layers 4, 6 and serves layer 7
HOST-02Mac Mini M18-core / 16GB — Docker via Colima, runs the vision stack (layer 5)
STOR-01External ExFAT driveFrigate recordings, clips, snapshots
// why

The Mac Mini was already-owned hardware, so the vision stack runs there instead of buying a dedicated NVR appliance or paying for cloud camera storage.

Colima's VM defaulted to 4 CPU / 6GB — half the M1's real capacity — which silently capped detection throughput. Resizing to 6 CPU / 10GB took combined detection FPS from 11.8 to 28.6 across three camera feeds.

LAYER 2 OSI analogue — Data link

Local network

Wired backbone plus two very different remote-access paths, each solving one specific problem.

NET-01Google Fiber ONT → Fiber RouterInternet handoff
NET-02TP-Link Deco XE75Mesh router, DHCP server
NET-03Netgear GS308Ev48-port managed switch
NET-04TP-Link PoE switchFeeds the 3 Reolink cameras
RMT-01TailscaleRemote access, zero open ports
RMT-02Cloudflare TunnelReverse proxy to a custom domain
// why

Two remote-access paths, two jobs: Tailscale for direct device/CLI access from outside the LAN, a Cloudflare Tunnel just so a push-notification snapshot image can load over cellular — without opening a port or running a VPN client on a phone just to see a photo.

Reading it the other direction

The page reads top-down. A real event climbs it bottom-up.

Here's one actual automation, traced through all seven layers — an unrecognized person showing up on the backyard camera.

L1 · PHYSICAL

The backyard camera sees a person

The RLC-1212A (12MP) captures motion and a person-shaped object enters its frame.

L2 · NETWORK

The frame reaches the LAN

PoE from the TP-Link switch, uplinked through the Netgear GS308Ev4.

L3 · COMPUTE

Frigate pulls the RTSP stream

Running in Docker on the Mac Mini, under Colima.

L4 · PROTOCOL

The event hits the bus

Frigate publishes to frigate/events on the Mosquitto broker.

L5 · VISION

Detection, then a face check

Object detector tags it person; face recognition finds no match, so sub_label stays empty.

L6 · LOGIC

cam_unknown_backyard evaluates

Person, inside backyard_zone, no sub_label, input_boolean.camera_automations_enabled is on, and the back door hasn't just opened — which would mean it's just a resident stepping outside.

L7 · PRESENTATION

Both phones buzz

notify.all_phones fires: "Someone unrecognized was detected in the backyard," with the event snapshot and a deep link into the dashboard.
